# GARIBALDI MARKET ORACLE - Codex Audit Results

This audit log records evidence-backed findings from `CODEX_ORACLE_DEEP_READINESS_AUDIT.md`.
Items are marked fixed only when both code and regression tests exist.

| ID | Severity | Subsystem | Evidence | Financial Consequence | Root Cause | Fix | Tests | Status | Remaining Risk |
|---|---|---|---|---|---|---|---|---|---|
| P0-001 | P0 | Market memory / Trade DNA provenance | `market_memory.record_closed_trade_memory()` previously selected the latest approved `oracle_decision_audit` row for a market/symbol when a trade closed. | A closed trade could be attributed to a later decision for the same symbol, contaminating Trade DNA, learning, and post-trade explanation with information that was not known at entry. | Entry lots and sell attribution did not persist immutable entry decision, signal, forecast, quote, correlation, model, provider, or snapshot identifiers. | Added immutable entry provenance fields to `position_lots`, `trade_ledger`, and `trade_dna`; propagated provenance from `_record_buy_attribution()` through FIFO sell attribution; `record_closed_trade_memory()` now queries only an exact entry decision identifier and never falls back to latest-by-symbol. | `test_closed_trade_memory_uses_immutable_entry_decision_not_later_symbol_decision` plus focused attribution tests; GitHub Actions PostgreSQL integration run `33514921579` passed. | CLOSED | Legacy lots created before these columns may have missing provenance; those remain conservative and are not enriched from latest mutable decisions. |
| P0-002 | P0 | Historical/as-of decision construction | `prediction_engine.build_decisions()` had no explicit historical decision timestamp filter for signals, forecasts, opportunities, or cached route metadata, and freshness used wall-clock time. | Backtests or historical audits could accidentally use future signals, later forecasts, or cache fetches newer than the decision time. | Decision assembly was optimized for current dashboard display and lacked an as-of guardrail. | Added optional `decision_timestamp`, `_known_at()` filtering, timestamp-aware signal selection, and as-of freshness checks for signal and forecast gates. | `test_asof_decision_excludes_future_signal_and_forecast_contamination`; `test_asof_decision_rejects_cache_route_newer_than_historical_decision_time`. | FIXED | Deeper raw-feature and news/event pipelines still need end-to-end as-of harness expansion in later audit stages. |
| P0-003 | P0 | Advisor decision identity | Oracle entry decisions could previously be represented with mixed vocabularies and insufficient evidence context. | Weak, negative, or unknown evidence could be made harder to distinguish from a genuine positive asymmetric opportunity. | Decision vocabulary and ten-question reasoning payload were local to recommendation assembly instead of shared and explicitly guarded. | Added `oracle_decision_identity.py`; advisor recommendations now use shared vocabulary and downgrade/mark missing evidence as WAIT/UNKNOWN rather than upgrading to BUY. | BUY, STRONG BUY, WAIT, AVOID, SELL/REDUCE, UNKNOWN coverage in `test_v36_advisor_foundation.py`. | FIXED | Other display surfaces should progressively adopt the same payload where they still render older records. |
| P0-004 | P0 | Probability / confidence truthfulness | `prediction_engine.build_decisions()` defaulted missing forecast `probability_up` to signal confidence. Advisor confidence had no machine-readable classification. | Heuristic confidence could be mistaken for a calibrated probability of profit/upside. | Probability-like fields were not classified by evidence source and calibration state. | Added `probability_evidence.py`; advisor and decision outputs now attach probability metadata. Missing forecast probability remains missing instead of being filled from confidence. | `test_probability_metadata_distinguishes_scores_from_calibrated_probabilities`; `test_missing_target_is_never_a_buy`; `test_fresh_price_and_target_can_remain_buy`. | FIXED | Additional modules still expose heuristic probability-like values and must be relabeled or validated in later audit passes. |
| P1-001 | P1 | Forecast validation | Mean-only calibration error could hide bad calibration inside probability buckets. | A model could appear acceptable while overconfident in specific confidence ranges. | Validation summary lacked Brier score, log loss, reliability buckets, ECE, MCE, interval coverage, confidence intervals, and effective sample size. | Expanded `ForecastValidationSummary` and `summarize_validation()` with reliability and calibration metrics while keeping model registry approvals unchanged. | `test_forecast_validation_summary_reports_calibration_and_reliability_metrics`. | FIXED | A full reproducible walk-forward pipeline, baselines, purging/embargo, and promotion artifacts remain required before any SHADOW model can be approved. |
